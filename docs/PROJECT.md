# koog-chat-tool — описание проекта

Дата: 2026-10-08. Фаза 1 (проектирование), задача T1.

## 1. Назначение

koog-chat-tool — HTTP-сервис (Kotlin/JVM), который предоставляет LLM инструмент сохранения истории чата: LLM (через механизм tool/function calling) отправляет диалог на эндпоинт `POST /tools/save-chat`, сервис сохраняет его в JSON-файл — один файл на диалог. Все вызовы LLM в самом проекте выполняются только через фреймворк Koog (JetBrains, `ai.koog`), а каждый запрос к LLM и ответ на него обязательно логируются в файл (JSONL с ротацией).

## 2. Цели

1. Дать LLM-агентам простой инструмент персистентности диалогов поверх HTTP (языко- и фреймворк-независимый контракт OpenAI tool calling).
2. Продемонстрировать каноничную интеграцию Kotlin/Ktor с фреймворком Koog: OpenAI-совместимый провайдер (OpenAI / DeepSeek / OpenRouter) из конфигурации.
3. Гарантировать наблюдаемость LLM-вызовов: полный JSONL-журнал «запрос → ответ/ошибка» с маскированием секретов и ротацией Logback.
4. Быть образцом качества: весь код с комментариями, тесты (юнит + интеграционные), CI в GitHub Actions.

## 4. Ограничения (вне scope)

- Нет авторизации на эндпоинте (решено: «по умолчанию без авторизации; добавить при необходимости») — точка расширения задокументирована.
- Нет БД и поиска по историям — только файлы (JSON, один на диалог).
- Нет потоковой передачи и многошаговых агентов — только одиночные chat-completion вызовы через Koog.
- Нет самостоятельных вызовов LLM в боевом режиме: эндпоинт `/llm/chat` существует лишь для верификации и по умолчанию отключён.
- Репозиторий — private на GitHub.
- Группа `ai.koog` отсутствует в индексе search.maven.org (проверено) — версии проверять по repo1.maven.org; на сборку это не влияет.

## 6. Архитектура

Детально: [docs/ARCHITECTURE.md](./ARCHITECTURE.md). Кратко: один Gradle-модуль; пакеты `config`, `model`, `storage`, `llm` (шлюз Koog + логирование), `tool` (JSON-схема инструмента), `routes`, `validation`; маршруты Ktor → хранилище файлов (атомарная запись, блокировки на диалог); LLM — только через `LlmGateway` на Koog (`OpenAILLMClient` + `MultiLLMPromptExecutor` + prompt DSL), обёрнутый в логирующий декоратор.

## 7. Definition of Done

Проект считается готовым, когда выполнены ВСЕ пункты:

1. Все вызовы LLM выполняются через фреймворк Koog (проверка: grep `ai.koog` — только в пакете `llm`; код-ревью T8).
2. Маршрутизация HTTP обрабатывается Ktor (Netty).
3. Каждый запрос к LLM и ответ на него логируется в файл `logs/llm-requests.log` (обязательное требование): события `llm.request` / `llm.response` / `llm.error`, JSONL, ротация Logback, секреты замаскированы — проверяется интеграционным тестом и QA.
4. История чата сохраняется в JSON — один файл на диалог (`storage/chats/`, настраивается).
5. Код содержит комментарии, поясняющие происходящее.
6. Тесты проходят (юнит + интеграционные), код-ревью и QA-верификация пройдены.
7. Проект загружен на GitHub в private-репозиторий `koog-chat-tool`, GitHub Actions CI (сборка + тесты) работает.

## 8. Репозиторий

- GitHub, ВИДИМОСТЬ: private.
- Создание: `gh repo create koog-chat-tool --private --source . --push` (ветка `main`).
- Защита секретов: `LLM_API_KEY` никогда не коммитится (только env/конфиг окружения), `.gitignore` включает `logs/`, `storage/`, `.gradle/`, `build/`, `.idea/`, `*.iml`.
- CI: `.github/workflows/ci.yml` (сборка + тесты на push/PR, кэширование Gradle через `gradle/actions/setup-gradle@v4`).
